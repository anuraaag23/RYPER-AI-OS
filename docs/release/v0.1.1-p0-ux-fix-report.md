## 1. Executive Summary

This milestone resolves the two blocking P0 user-experience defects identified during the **v0.1.0 First-Run UX Audit** (`docs/release/v0.1.0-first-run-ux-audit.md`):

1. **P0-1 — Missing Permission Management & Consent UI**:
   - In v0.1.0, ungranted capabilities (e.g. `applications.execute`) produced an inescapable dead-end where the model instructed the user to grant permissions, but no UI prompt or settings view existed.
   - **Resolution:** Implemented an accessible permission consent modal in the UI with plain-English capability descriptions, "Allow once" and "Deny" choices, safe default focus on "Deny", focus trapping, Escape-to-deny, safe error handling on denial, automatic resumption on approval, and an authoritative Permissions card in Settings with "Reset Session Permissions".

2. **P0-2 — Hidden Composer on Clean First Launch**:
   - In v0.1.0, launching with 0 conversations left `activeId` undefined, completely hiding the composer input and leaving users with a blank screen.
   - **Resolution:** On clean first run, an initial conversation is automatically created, the composer is immediately visible, and an interactive welcome hero ("Hi, I'm RYPER.") is rendered with suggested prompt chips (`[ Check my battery ]`, `[ Open Notepad ]`, `[ What can you do? ]`). Subsequent relaunches preserve existing conversation history without creating duplicate conversations.

All 235 test suites across the monorepo pass (1,615 passed / 13 skipped / 0 failed, up from 1,606 in v0.1.0). The frozen v0.1.0 installer and Git tag remain completely immutable.

## 2. P0-1: Permission Management & Consent UI Implementation

### Architecture & Data Flow

Privilege separation remains strictly enforced:
- **Renderer Sandboxing:** The renderer never possesses authority to directly grant capabilities.
- **Authoritative Enforcement:** Capabilities are evaluated in the Electron main process via `CapabilityBroker` and `CapabilityManager`.
- **Consent Mediation:** When an ungranted capability is requested, `main.ts` intercepts the request, transforms it via `describeCapabilityRequest()`, and invokes `ConfirmationBridge.prompt(title, message, approveLabel, denyLabel)`.
- **Renderer Dialog:** `ConfirmationDialog.tsx` displays the dialog, moves initial keyboard focus to the "Deny" button, traps Tab navigation, and binds Escape to "Deny".
- **Action Resumption:** Clicking "Allow once" resolves the confirmation promise `true`, grants the session permission in `CapabilityBroker`, and allows the original Windows operation to complete without re-prompting.
- **Denial Sanitization:** If denied, `summarizeForDisplay()` in `tool-activity.ts` converts the denial into `"Permission was denied by the user. The action was cancelled."`, preventing raw internal capability and actor IDs from leaking into user-facing tool activity cards.
- **Destructive Separation:** Destructive power operations (`shutdown`, `restart`, `sleep`) remain governed by `DestructiveActionGate` / `PowerConfirmationManager`, completely independent of capability consent.

### Settings Permissions Management
- `SettingsApp.tsx` now renders an authoritative "Permissions" card listing all six capability domains:
  - Application Control (`applications.execute`)
  - Window Management (`windows.manage`)
  - File Access & Storage (`files.read`, `files.write`)
  - Notifications (`notifications.show`)
  - Power Management (`system.power`)
  - Audio & Microphone (`audio.record`)
- Live status badges show whether each category is "Ask each time" or "Allowed this session".
- A "Reset Session Permissions" button invokes `IPC_CHANNELS.resetPermissions`, clearing session grants from `CapabilityBroker`.

## 3. P0-2: First-Launch Composer & Welcome State Implementation

### Architecture & State Management

- **Clean Launch Detection:** `App.tsx` monitors `useConversations()` with a dedicated `loaded` flag. When `loaded && ready` and `conversations.length === 0`, it auto-creates an initial conversation and sets `activeId`.
- **Restart Non-Duplication:** On subsequent launches where conversations exist, auto-creation is skipped, selecting the most recent conversation instead.
- **Welcome Hero:** When `messages.length === 0`, `ChatPanel.tsx` renders:
  - Title: *"Hi, I'm RYPER."*
  - Subtitle: *"I can answer questions, work with your Windows PC, manage files and apps, and talk with you by voice."*
  - Prompt: *"Try asking me something:"*
  - Interactive Suggestion Chips: `[ Check my battery ]`, `[ Open Notepad ]`, `[ What can you do? ]`.
- **Immediate Composer Availability:** The composer input (`.composer-input`) is always rendered and visible in the footer, fully keyboard accessible on first launch.
- **One-Click Dispatch:** Clicking any suggestion chip immediately dispatches the turn.
