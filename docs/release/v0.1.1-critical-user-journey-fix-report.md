## 3. Detailed Defect Analysis & Architectural Fixes

### Defect 1: Microphone Input in Installed Application
- **Root Cause**: Electron default session previously only checked for permission name `"media"`. In Chromium runtime, `navigator.permissions.query({ name: "microphone" })` and modern Web Audio APIs query for `"microphone"` or `"audio-capture"`, causing permission queries to return `permission-denied`.
- **Fix**:
  - `platform/desktop-app/electron/windows.ts`: Configured `setPermissionRequestHandler` and `setPermissionCheckHandler` on `session.defaultSession` to explicitly approve `"microphone"`, `"audio-capture"`, and `details.mediaTypes.includes("audio")`.
  - `platform/desktop-app/src/audio/capture-client.ts`: Added graceful fallback to `{ audio: true }` if device-constrained `getUserMedia` encounters hardware initialization errors.

### Defect 2: Push-to-Talk (Ctrl + Shift + Space) Shortcut Inactive
- **Root Cause**: Global shortcut was never registered in Electron's main process via `globalShortcut.register()`, the system tray PTT handler only emitted an event without triggering the turn, and renderer lacked a global keydown listener.
- **Fix**:
  - `platform/desktop-app/electron/main.ts`: Registered `CommandOrControl+Shift+Space` using Electron `globalShortcut` with clean unregistration on `will-quit`. Initialized `mainWindow` early so `webContents` is immediately available. Guarded turn execution with `isVoiceTurnRunning` mutex.
  - `platform/desktop-app/src/App.tsx`: Added window-level keydown listener for `Ctrl+Shift+Space` dispatching `window.ryper.startVoiceTurn()`.

### Defect 3: Voice UI Active But Activation Unreliable
- **Root Cause**: The voice activity detector (`EnergyVoiceActivityDetector`) had an energy threshold of `500`, which was too high for standard desktop condenser microphones, causing user speech to be classified as silence. In addition, missing initial silence timeouts left the pipeline listening indefinitely.
- **Fix**:
  - `platform/desktop-app/electron/voice-bootstrap.ts`: Calibrated `energyThreshold` to `200` for typical desktop speech levels.
  - `platform/desktop-app/electron/voice-pipeline.ts`: Added 50-frame (~12s) initial silence timeout to `endpointedFrames` to prevent hanging, and ensured state machine cleans up non-idle states before starting new turns.

### Defect 4: "Open Downloads" Repeatedly Opening "Documents"
- **Root Cause**: `windows-adapter.ts` and `desktop-actions.ts` passed raw string `"downloads"` directly to `explorer.exe`. Without an absolute filesystem path or Windows virtual CLSID, launching `explorer.exe downloads` resolves relative to the current working directory, which defaults to the user profile or Documents folder.
- **Fix**:
  - `core/windows-agent/src/powershell-system-api.ts` & `reference-system-api.ts`: Resolved known folder aliases (`downloads`, `desktop`, `documents`, `pictures`, `videos`, `music`) via `getWellKnownFolderPath` before invoking explorer.
  - `platform/desktop-app/electron/desktop-actions.ts`: Added `filesystem.well_known_folder` resolution for folder targets.
  - `platform/desktop-app/electron/voice-commands.ts`: Added intent patterns for opening standard known folders.

### Defect 5: Conversational Correction ("Not Documents, Downloads") Ignored
- **Root Cause**: Target parser in `desktopActions.openApplication` treated the entire user phrase verbatim without stripping conversational negation/repair markers.
- **Fix**:
  - `platform/desktop-app/electron/desktop-actions.ts`: Added conversational repair regex stripping prefixes (`no,`, `i said`) and negation tails (`, not <target>`).
  - Added support for re-execution triggers (`again`, `it again`, `fir se`, `phir se`, `dobara`) routing directly to `openContextualReference`.

### Defect 6: Local AI Multi-Round Tool Calling Wire Format Inconsistency
- **Root Cause**: In multi-round tool calling, `AIOrchestrator` appended user turns directly followed by tool result turns without an intervening assistant turn containing `tool_calls`. OpenAI-compatible engines (such as `llama-server`) throw an HTTP 400 or template rendering error when a `tool` role message does not follow an assistant message with `tool_calls`.
- **Fix**:
  - `core/ai-engine/src/orchestrator.ts`: Appended `{ role: "assistant", content: roundText, toolCalls: pendingToolCalls }` before invoking tools.
  - `core/ai-engine/src/providers/openai-compatible.ts`: Serialized `tool_calls: [...]` on assistant messages in `streamChat`.

### Defect 7: Cold Local AI Inference Latency (70–120s)
- **Root Cause**: `LlamaServerManager` launched `llama-server` without GPU layer offloading (`-ngl`) or flash attention (`--flash-attn`), forcing 100% CPU inference on quantized weights.
- **Fix**:
  - `platform/desktop-app/electron/llm-model-provisioning.ts`: Added `-ngl 99` (offloading all layers to available Vulkan/DirectX/CUDA GPU, with safe CPU fallback) and `--flash-attn` to `llama-server` arguments.

### Defect 8: Session-Only Permissions Without Persistence
- **Root Cause**: `CapabilityBroker` stored decisions exclusively in an in-memory `Map`. On restart, all user approvals were discarded, causing constant prompts. The UI offered no way to remember choices or configure policies.
- **Fix**:
  - `core/security/src/index.ts`: Introduced `PermissionPolicy = "always" | "prompt" | "denied"` with `setPolicy`, `getPolicy`, `exportPolicies`, and `importPolicies`. `requestCapability` checks policy before prompting.
  - `platform/desktop-app/electron/settings-store.ts`: Added `persistentPermissions` dictionary to `AppSettings` schema with atomic persistence.
  - `platform/desktop-app/electron/core-bootstrap.ts`: Loaded persisted policies into `CapabilityBroker` on boot.
  - `platform/desktop-app/src/components/ConfirmationDialog.tsx`: Added "Always Allow" button to grant permanent policy directly from consent modal.
  - `platform/desktop-app/src/SettingsApp.tsx`: Added dropdown policy selector ("Always allow", "Ask each time", "Block") for every capability.

### Defect 9: Voice Accent Selection Limited to Auto
- **Root Cause**: Piper voice registry only registered `en-US` Lessac and `hi-IN` Hindi. Hinglish/Romanized Hindi lacked Devanagari characters, causing `resolveVoiceId` to always default to US English.
- **Fix**:
  - `platform/desktop-app/electron/voice-bootstrap.ts`: Registered `en-IN` (Indian English) alongside `default` (US English) and `hindi` (Hindi).
  - `platform/desktop-app/electron/voice-pipeline.ts`: Added vocabulary matching for common Hinglish terms (`\b(?:hai|karo|khol|kholo|diya|chalao|roko|gaana|aawaz|badhao|namaste|dhanyawad|shukriya|aap|kaise|kya|bhai|theek|accha)\b/i`) to route spoken queries to Indian voice models.
  - `platform/desktop-app/src/SettingsApp.tsx`: Exposed English (US), English (India / Indian Accent), and Hindi in the settings UI.

### Defect 10: Conversational Fallback Tone & Helpfulness
- **Root Cause**: When queries did not match regex patterns and local LLM was initializing, heuristic provider responded with a mechanical failure notice ("I don't have a pattern-matched way... this fallback isn't a language model").
- **Fix**:
  - `platform/desktop-app/electron/heuristic-ai-provider.ts`: Added natural conversational responses for greetings ("hello", "namaste"), identity ("who are you"), status ("how are you"), thanks ("thank you", "dhanyawad"), and guidance on supported commands while preserving contractual fallback text for unhandled commands.

### 8.2 Push-to-Talk (Ctrl + Shift + Space) Physical Trace

The end-to-end hotkey dispatch path was traced and verified:
1. **Windows OS**: User presses `Ctrl + Shift + Space` anywhere in Windows.
2. **Win32 HotKey**: `WM_HOTKEY` caught by Electron's `globalShortcut` handler in `platform/desktop-app/electron/main.ts`.
3. **Window State Handling**:
   - *State 1 (Focused)*: Main window receives focus confirmation; dispatches turn.
   - *State 2 (Minimized/Hidden)*: Calls `mainWindow.show()` and `mainWindow.focus()`, surfacing RYPER to the foreground.
   - *State 3 (Unfocused / Other App active, e.g. Notepad)*: Calls `mainWindow.focus()`, successfully stealing focus and starting voice capture.
4. **Renderer Notification**: Emits IPC `voice:state` (`{ orbStatus: "listening", connection: "connected" }`).
5. **Orchestrator Turn**: Invokes `core.voice.pipeline.runTurn()`.
- **Test Suite**: Dedicated automated test suite in `platform/desktop-app/test/ptt-shortcut-trace.test.ts` passed across all three window states.

### 8.3 Local Qwen3 Latency Root-Cause Breakdown

Two architectural bottlenecks were diagnosed and resolved:
1. **Multi-Slot KV Cache VRAM Blowup**:
   - `llama-server` defaulted to `-np 4` (4 parallel slots). At context size 8192, this allocated 4 × 8,192 = 32,768 tokens (~4.6 GB VRAM) for KV cache. Combined with 4.45 GB model weights, the 9.1 GB requirement exceeded the 6.1 GB physical VRAM of the laptop RTX 4050 GPU, triggering CUDA memory rejection (`common_fit_params: failed to fit params to free device memory: n_gpu_layers already set by user to 99, abort`) and fallback to shared host RAM paging over PCIe.
   - **Fix**: Configured `-np 1` (desktop assistant is single-user) and default context size 4096 (`-c 4096`). Total KV cache dropped to 576 MiB, allowing 100% of model layers and KV cache to fit comfortably in 5.6 GB of dedicated GPU VRAM with zero paging.
2. **4,146-Token Redundant Tool Schema Prefill**:
   - `AIOrchestrator` previously sent all 81 tool specifications on every request. Serialized in JSON, these schemas consumed 4,146 tokens. For simple conversational queries ("Hello", "Why is the sky blue?"), Qwen3 had to prefill 4,178 prompt tokens at ~150 tok/s (~28 seconds) before generating the first token.
   - **Fix**: Introduced `ToolSelector` architecture in `core/ai-engine/src/orchestrator.ts` and wired `createDesktopToolSelector()` in `platform/desktop-app/electron/desktop-tool-selector.ts`. Pure conversational queries receive 0 tools (prompt tokens: ~40, TTFT: ~2-6s). System action queries receive targeted domain subsets (500–1,500 prompt tokens).

### 10.2 Real-World Physical Edge Cases Diagnosed and Resolved

During live physical testing against the physical microphone, 8 critical hardware/OS interaction bugs were uncovered and surgically resolved in the codebase:

1. **VAD Laptop Fan Noise Saturation**:
   - *Root Cause*: `EnergyVoiceActivityDetector` hardcoded `energyThreshold: 200`. Active cooling fans under local GPU/CPU load generated steady acoustic noise up to RMS 522.7. VAD never detected trailing silence, accumulating $>400$ speech frames and triggering `VoiceSessionManager`'s 15-second cancellation timeout.
   - *Fix*: Made VAD threshold configurable via `Number(process.env.RYPER_VAD_THRESHOLD) || 500`. With threshold set to 650, ambient fan noise ($<523$) is cleanly rejected while live human speech ($>1,200$) is detected immediately and endpoints in $\approx 1.7\text{s}$.
2. **Acoustic Self-Feedback / Barge-In Loop**:
   - *Root Cause*: Hardware Acoustic Echo Cancellation (AEC) is not supported by default in DirectShow capture. When Piper played TTS responses through the laptop speakers, the laptop microphone captured its own voice ($\text{RMS} \approx 325$), immediately aborted playback, and fed phantom transcripts back into Qwen3 in an infinite loop.
   - *Fix*: Set `RYPER_ENABLE_BARGE_IN=false` during physical pipeline execution to disable microphone capture while speaker playback is active.
3. **Renderer Audio Bridge Playback Timeout**:
   - *Root Cause*: `RendererAudioBridge.play()` hardcoded a fixed 8,000ms timeout (`this.timeoutMs = 8000`). Multi-sentence spoken responses exceeding $\approx 15$ words took $>8\text{s}$ to play (e.g. 9.73s), causing the bridge to throw `renderer audio bridge did not confirm playback completion within 8000ms` and crash the turn into `error`.
   - *Fix*: Added `playbackTimeoutMs` (default 60,000ms) to `RendererAudioBridgeOptions` in `audio-bridge.ts`.
4. **Invalid Voice Session Transitions on Cancellation**:
   - *Root Cause*: If a voice session was cancelled by timeout while capture was running, `sessionManager.transition("thinking")` threw `InvalidVoiceSessionTransitionError: cannot transition voice session from "cancelled" to "thinking"`.
   - *Fix*: Guarded transitions to `transcribing`, `thinking`, `speaking`, and `idle` against `cancelled`, `error`, and `idle` states in `voice-pipeline.ts`.
5. **Whisper `[BLANK_AUDIO]` Hallucination**:
   - *Root Cause*: When Whisper transcribed room silence, it emitted `"[BLANK_AUDIO]"`, which was passed to Qwen3 as a valid user prompt.
   - *Fix*: Added `finalText.trim() === "[BLANK_AUDIO]"` check in `voice-pipeline.ts` to treat blank audio as empty speech.
6. **Windows 11 Tabbed Explorer Window Detection**:
   - *Root Cause*: `(New-Object -ComObject Shell.Application).Windows()` returns empty on Windows 11 tabbed Explorer frames.
   - *Fix*: Created Win32 `EnumWindows` and `GetWindowText` inspection helper to detect and verify `Downloads - File Explorer`.
7. **Punctuation Normalization in Known Folder Resolution**:
   - *Root Cause*: Whisper STT produces transcripts with trailing punctuation (e.g. `"Open downloads, folder."`). Periods and commas prevented regex matching in known folder aliases.
   - *Fix*: Sanitized punctuation in `core/windows-agent/src/path-resolver.ts` and `platform/desktop-app/electron/desktop-actions.ts`.
8. **Pre-authorized Actor Grants for Desktop Automation**:
   - *Root Cause*: Voice turns requiring automation were blocked waiting for interactive UI confirmation dialogs.
   - *Fix*: Pre-authorized `"automation.execute"`, `"automation.read"`, and `"filesystem.read"` for `ai-orchestrator` and `voice-session` in `platform/desktop-app/electron/core-bootstrap.ts`.

## 12. Final Voice Permission Security Audit & Official Verdict

### 12.1 Background & Audit Rationale
In the previous physical voice verification pass, pre-authorizations for `"automation.execute"`, `"automation.read"`, and `"filesystem.read"` were introduced for `ai-orchestrator` and `voice-session` inside `platform/desktop-app/electron/core-bootstrap.ts`.
This security audit was commissioned to determine:
1. Exactly why these grants exist.
2. Whether they bypass the user's permission policy in Settings.
3. Whether destructive operations could be bypassed.
4. Whether user policies survive application restart.
5. What architectural remediation was required to make user policy supreme across both chat and voice.

### 12.2 Critical Findings
1. **Grant Rationale**:
   - In `WINDOWS_CAPABILITY_DESCRIPTORS`, ordinary actions like opening a folder or launching an app require `automation.execute`, reading power status requires `automation.read`, and browsing files requires `filesystem.read`.
   - `CapabilityBroker` defaults to policy `"prompt"`. Under `"prompt"`, `broker.requestCapability()` triggers a 60-second interactive modal consent dialog on the desktop screen.
   - For hands-free voice operations (and global PTT `Ctrl + Shift + Space` hotkeys while the window is unfocused), modal pop-ups caused voice interactions to stall and time out with `permission denied`.
   - The grants were added to allow safe, non-destructive voice commands and tools to succeed out-of-the-box.
2. **Identified Flaws & Bypasses in Prior Implementation**:
   - **Startup Overwrite**: On boot, `core-bootstrap.ts` called `broker.grant(...)` unconditionally before reading `settings.json`.
   - **Grant Precedence Inversion**: `CapabilityBroker.hasGrant()` returned `true` if `this.grants.get(...) === "granted"` without verifying if `this.getPolicy()` was `"denied"`.
   - **Actor Scope Disconnect**: In `ipc-handlers.ts`, `setPermissionPolicy` only configured `ai-orchestrator`, leaving `voice-session` unmanaged.
   - **UI Discrepancy**: Settings -> Permissions UI displayed `Always allowed` even when the policy dropdown was set to `Block` because `granted` was tied to the unmanaged grant.
3. **Destructive Safety Verification**:
   - **VERIFIED SAFE**: `DestructiveActionGate` (`core/windows-agent/src/confirmation.ts`) is completely decoupled from `CapabilityBroker`.
   - All destructive actions (`shutdown`, `restart`, `sleep`, `delete_file`, critical process kill, critical service modification, registry writes) unconditionally require explicit confirmation via `destructiveActionConfirmer`. Pre-authorizations in `CapabilityBroker` CANNOT bypass `DestructiveActionGate`.

### 12.3 Architectural Remediation Applied
1. **Policy Supremacy in `CapabilityBroker` (`core/security/src/index.ts`)**:
   - `hasGrant(actorId, capability)`: If `this.getPolicy(capability, actorId) === "denied"`, it immediately returns `false`. If `"always"`, it returns `true`. If `"prompt"`, it checks for session consent.
   - `setPolicy(capability, policy, actorId)`: Correctly propagates `"denied"` and `"prompt"` to revoke grants across both specific actors and global wildcard keys.
   - `importPolicies(policies)`: Routes directly through `setPolicy()`, ensuring imported policies immediately synchronize all grant tables.
2. **Dual-Actor Parity in IPC Handlers (`platform/desktop-app/electron/ipc-handlers.ts`)**:
   - `setPermissionPolicy`: Updates policies for `ai-orchestrator`, `voice-session`, and global scope simultaneously.
   - `resetPermissions`: Revokes grants and resets policies to `"prompt"` for both actors and global scope.
3. **Clean Boot Lifecycle in `core-bootstrap.ts`**:
   - Settings are loaded before platform agent initialization.
   - Default out-of-the-box pre-authorizations are applied ONLY if no user policy exists in `settings.persistentPermissions`.
   - Persistent policies are imported immediately on startup, ensuring user decisions are authoritative from boot.
