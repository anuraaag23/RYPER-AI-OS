## 2. P2 Implementation Details

### P2-1: Local AI Status Popover
- **Problem**: Header status was a static indicator offering no explanation of on-device privacy, offline capability, or first-turn startup warm-up latency.
- **Solution**:
  - Upgraded `.ai-status-indicator` into an accessible toggle button (`aria-expanded`, `aria-haspopup="dialog"`, keyboard Enter/Space toggle, click-outside and Escape dismissals).
  - Designed `.ai-status-popover` explaining:
    - **On-Device & Private**: Running locally on your computer; conversations never leave your device.
    - **Works Offline**: Full AI intelligence available without an active internet connection.
    - **First-Turn Startup**: Transparent explanation that the first query warms the model into memory.
  - Zero technical leakage: no port numbers (`8090`), no `127.0.0.1`/`localhost`, no filesystem paths, and no internal engine identifiers.

### P2-2: Long-Wait Communication
- **Problem**: Queries taking longer than 10-15s gave no elapsed-time awareness or feedback, making the app appear frozen.
- **Solution**:
  - Added elapsed-time awareness tracking in `ChatPanel.tsx` (>12s elapsed threshold).
  - Displays reassuring copy: `"Still working — local AI can take a little longer for complex requests."`.
  - Added `.pending-pulse` glowing CSS animation so the UI continuously displays visible life.
  - Real Cancel control (`window.ryper.cancelTurn()`) is preserved and remains clickable at all times during flight.

### P2-3: Friendly Device & Diagnostic Language
- **Problem**: Audio devices in Settings displayed Windows endpoint GUIDs (e.g. `({0.0.0.00000000}.{...})`), shortcut displayed Electron accelerator string `CommandOrControl+Shift+Space`, tool names showed raw snake_case (`system_run_app`), and routing badge showed raw string `local`.
- **Solution**:
  - Implemented `formatAudioDeviceName()` in `SettingsApp.tsx` stripping parenthesized GUIDs and raw hex strings while preserving friendly names like `Speakers` or `Microphone Array`.
  - Implemented `formatShortcutForDisplay()` displaying Windows-native `Ctrl + Shift + Space` with two-way parsing back into Electron accelerator format.
  - Implemented `formatToolName()` in `MessageBubble.tsx` converting internal tool names into clear actions (`Open Application`, `Check Power Status`, `Adjust Volume`, `Open Browser`, etc.).
  - Replaced raw routing badges with friendly badges: `🔒 On-Device (Private)` and `☁️ Cloud AI`.

### P2-4: Voice UX Polish
- **Problem**: Voice orb states and composer mic button lacked discoverability and shortcut guidance; Settings lacked explanation of multilingual code-switching.
- **Solution**:
  - Added push-to-talk shortcut tooltip `(Ctrl + Shift + Space)` to idle VoiceOrb and Composer mic buttons.
  - Clear state captions maintained: `Tap to talk`, `Listening…`, `Thinking…`, `Speaking…`.
  - Added Settings helper copy: `"Automatically understands spoken English, Hindi, and Hinglish."` without fabricating non-existent speech engines.

### P2-5: Settings & Permissions Polish
- **Problem**: Permissions management needed clear categorization and empty state clarity.
- **Solution**:
  - Verified human-readable capability categories (`Application Control`, `Window Management`, `File Access`, `File Storage`, `Notifications`, `Power Management`).
  - Added empty-state fallback: `"No special permissions requested yet this session."`.
  - Maintained `Reset Session Permissions` button and active IPC revoking session grants while keeping non-session defaults safe.

### P2-6: Error UX Polish & Sanitizer Policy
- **Problem**: Error messages required friendly copy while maintaining strict safety policies regarding completed actions and retries.
- **Solution**:
  - Preserved exact certified P1 offline error: `"RYPER couldn't complete that request. The local AI isn't responding right now."` with `canRetry: true`.
  - Preserved completed action error policy: `"The action was performed (...), but RYPER couldn't generate a summary."` with `canRetry: false`.
  - Cancellation errors cleanly mapped to non-retryable `"Request was cancelled."`.
  - Expanded friendly tool names to cover all `system_*` capabilities and added clean space-separated fallbacks.

### P2-7: Product Incompleteness Signals
- **Problem**: Splash screen startup steps exposed internal developer acronyms like `(wake word, VAD, STT/TTS, session, commands, memory)`.
- **Solution**:
  - Implemented `formatStartupStep()` in `SplashOverlay.tsx`.
  - Replaced developer jargon with human-readable labels:
    - `"Voice recognition & speech synthesis"`
    - `"Core system services"`
    - `"Security & permissions system"`
    - `"Windows desktop integration"`
    - `"Local AI engine"`
