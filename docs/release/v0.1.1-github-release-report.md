## 6. Documented Known Limitations

The following 8 known limitations are formally documented and accepted for the v0.1.1 release:

1. **Wake Word Detection:** The wake-word subsystem uses an energy-based audio threshold fallback. Continuous on-device deep-learning wake-word detection is **NOT independently certified**.
2. **TTS Acoustic Verification:** Piper TTS speech generation is validated at the bridge and audio-file level; perceptual acoustic fidelity across various speaker outputs has **NOT been independently certified by human hearing**.
3. **P1 Test 3 (Completed-Action Retry Safety):** Remains documented as *"Not independently verified — implementation covered by unit tests."*
4. **Local Qwen3-8B Hybrid GPU/CPU Prefill Latency:** On systems with limited free GPU VRAM, initial tool-schema prompt prefills (over 7,500 tokens) execute via hybrid CPU offload, requiring 70–120 seconds on the first cold turn before KV prefix caching takes effect. Subsequent turns execute in 1–3 seconds.
5. **Plugin Isolation:** In-process plugins execute within the trusted application runtime and are **NOT sandboxed for untrusted third-party code**.
6. **Settings Storage:** Local application preferences (`settings.json`) are stored as plaintext JSON in `%APPDATA%\ryper-desktop`, not encrypted with Windows DPAPI.
7. **Code Signing:** Windows installer binaries are not signed with an EV/OV Authenticode certificate. Windows SmartScreen warnings are expected on initial download.
8. **Update Delivery:** There is no silent in-app auto-update mechanism; updates require manual installer download from GitHub releases.
