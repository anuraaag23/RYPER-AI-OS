## 2. Truthful Microphone & Voice State Architecture

### Root Cause Diagnosis
1. **Misleading Connection Status Override in UI**: `VoiceOrb.tsx` had a mapping where `connection === "offline"` unconditionally overwrote the orb's status caption with `"Offline"`.
2. **Permanent Sticky Error Latch**: In `main.ts`, any error, timeout, or cancellation in `executeVoiceTurn()` previously dispatched `connection: "offline"`. Because no subsequent event reset `connection` back to `"connected"`, the UI remained permanently stuck displaying `"Offline"`.
3. **Coupled Network vs. Local Audio State**: The voice assistant operates 100% locally on-device (Whisper STT, Qwen3 LLM via llama-server, Piper TTS). Conflating internet network availability with local audio device readiness produced false offline indications.
4. **Startup Race Conditions**: Hardware status broadcasts occurred prior to renderer readiness without guaranteed synchronous initial state delivery upon `did-finish-load`.

### Architectural Remediation
- **Decoupled State Machine**: Distinguishes Network, Local AI, Microphone hardware, and Voice Engine pipeline states. Disconnection from the internet never marks local AI or the physical microphone as offline.
- **Truthful UI State Labels**:
  - Active Turns: `"Listening…"`, `"Thinking…"`, `"Speaking…"` (never overridden by connection state).
  - Ready / Idle: `"Tap to talk"` (with tooltip `"Tap to talk (Ctrl + Shift + Space)"`).
  - Hardware Unavailable: `"Microphone unavailable"` (with actionable tooltip).
  - Permission Denied: `"Microphone access is off"` (with settings guidance tooltip).
  - Reconnecting: `"Reconnecting…"` (only during active degraded connection retries).
- **Session Transition Event Binding**: Bound `VoiceSessionManager`'s `voice_engine.session_transition` events directly through the `EventBus` to the renderer, providing live visibility into `listening`, `transcribing`, `thinking`, `tool_execution`, and `speaking` states.
- **Clean Error Recovery**: Catch blocks in `main.ts` reset `orbStatus: "idle"` and `connection: "connected"`, guaranteeing the UI always recovers cleanly to ready.
- **Zero Startup Race Condition**: Synchronously broadcasts initial voice and audio states on `webContents` `did-finish-load`.

## 3. Permission & Voice Security Audit Remediation

The security audit of pre-authorizations (`automation.execute`, `automation.read`, `filesystem.read`) confirmed:
1. **User Policy Supremacy**: In `CapabilityBroker`, `hasGrant(actorId, capability)` checks user policy first. If policy is `"denied"`, access is immediately refused regardless of prior grants.
2. **Persistence Guarantee**: Settings are loaded before platform agent initialization. Persisted user policies take precedence over bootstrap default pre-authorizations and survive application restarts.
3. **Actor Scope Parity**: Changing permissions in Settings applies across `ai-orchestrator`, `voice-session`, and global scope simultaneously.
4. **Inviolable Destructive Action Barrier**: `DestructiveActionGate` operates independently of capability grants. Destructive actions (system shutdown, restart, file deletion, process killing, service modification, registry writes) unconditionally require user confirmation via `DestructiveActionGate`.
5. **UI Transparency**: Permissions UI truthfully reflects `granted: false` when a policy is set to `"denied"`.
