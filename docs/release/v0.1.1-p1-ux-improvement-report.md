## 1. Executive Summary

Following the completion and certification of the v0.1.1 P0 UX fixes, the v0.1.1 P1 milestone addressed the remaining three priority UX issues identified in the First-Run UX Audit (`docs/release/v0.1.0-first-run-ux-audit.md`):

1. **P1-1: Local AI Status & Long-Run Progress UX**
   - Added a friendly, transparent AI status indicator pill in the chat header (`Local AI • Qwen3-8B` / `Running locally`) that never exposes raw provider strings, ports, or internal actor IDs.
   - Implemented dynamic real-time progress states ("Thinking…", "Checking your battery…", "Opening Notepad…", "Working on it…", "Finishing up…") with a 7-second warm-up explanation during local model prefill.
   - Built with strict accessibility compliance (`role="status"`, `aria-live="polite"`, `aria-label`).

2. **P1-2: Friendly Error Recovery & Safe Retry**
   - Implemented `sanitizeUserFacingError` to eliminate all raw technical strings (`ProviderError`, `ECONNREFUSED`, `127.0.0.1:8090`, `llama-cpp-local`, file paths, stack traces, and capability IDs).
   - Added a visible, safe "Retry" button that re-dispatches the turn through standard IPC (`sendMessage`), ensuring all permission gates and destructive action confirmations remain 100% authoritative.
   - Added protection against repeating already-executed Windows actions (`action_completed` flag disallows retry and explains what succeeded).

3. **P1-3: Clean Up "Coming Soon" Navigation**
   - Removed all 6 disabled sidebar navigation buttons (`Memory`, `Plugins`, `Models`, `Automation`, `Documents`, `Diagnostics`) and the "More" section header.
   - Cleanly preserved the functional `Settings` button at the bottom of the sidebar.

## 2. Implementation Details

### 2.1 Contracts & Preload Surface
- **`platform/desktop-app/electron/ipc-contract.ts`**:
  - Declared `AIStatusPayload` (`mode`, `label`, `ready`).
  - Declared `TurnProgressStage` (`"thinking" | "warmup" | "tool" | "generating"`) and `TurnProgressPayload` (`conversationId`, `turnId?`, `stage`, `label`).
  - Added `IPC_CHANNELS.getAIStatus` (`"ai:status"`) and `IPC_CHANNELS.turnProgress` (`"turn:progress"`).
  - Extended `RyperInvokeApi` with `getAIStatus()` and `RyperEventApi` with `onTurnProgress()`.
- **`platform/desktop-app/electron/preload.ts`**:
  - Safely exposed `getAIStatus` and `onTurnProgress` to the renderer with typed contract enforcement.

### 2.2 Main Process Engine & Turn Execution
- **`platform/desktop-app/electron/text-chat.ts`**:
  - Added `TurnProgressCallback` and `describeToolProgress(toolName, args)` for human-friendly tool action descriptions (`"Opening <app>…"`, `"Checking your battery…"`, `"Adjusting volume…"`, `"Checking files…"`, `"Finding window…"`, etc.).
  - Added 7-second prefill warm-up timer for local AI turns emitting `"The local AI is warming up. This can take a little longer the first time."`.
  - Emitted real-time progress on tool calls, tool results, and generating text deltas.
  - Added execution tracking that catches tool successes prior to downstream summarization errors, packaging them as `action_completed:<toolName>:<details>`.
- **`platform/desktop-app/electron/ipc-handlers.ts`**:
  - Implemented `IPC_CHANNELS.getAIStatus` handler mapping engine states to human labels (`Local AI • Qwen3-8B`, `Cloud AI`, or `Running locally`).
  - Added `broadcastProgress` broadcasting turn progress to chat renderer windows.
  - Wired progress callbacks in both `sendTurn` and `regenerateMessage`.

### 2.3 Renderer Architecture & Sanitization
- **`platform/desktop-app/src/lib/user-error-sanitizer.ts`**:
  - Strips all technical error indicators: `ProviderError`, `llama-cpp-local`, `ECONNREFUSED`, ports, IP addresses, URLs, stack traces, and internal actor IDs.
  - Maps error conditions to friendly messages:
    - Local AI disconnected: `"RYPER couldn't complete that request. The local AI isn't responding right now."` (`canRetry: true`).
    - Cloud/quota unavailable: `"RYPER couldn't complete that request. The AI service is currently unavailable."` (`canRetry: true`).
    - Action succeeded before summary failed: `"The action was performed (${friendlyAction}), but RYPER couldn't generate a summary."` (`canRetry: false`).
    - Cancellation: `"Request was cancelled."` (`canRetry: false`).
    - Generic fallback: `"RYPER couldn't complete that request."` (`canRetry: true`).
- **`platform/desktop-app/src/hooks/useRyperData.ts`**:
  - Implemented `useAIStatus()` hook with graceful fallbacks.
  - Updated `useMessages()` to listen to `onTurnProgress`, track pending `progress`, sanitize turn errors, track `lastFailedContent`, and expose `canRetry` and `retry()`.
- **`platform/desktop-app/src/components/ChatPanel.tsx`**:
  - Added top header with `.ai-status-indicator`, emerald dot `.ai-status-dot`, and accessibility label `role="status"`.
  - Updated pending message bubble to render dynamic `{progress?.label ?? "Thinking…"}` with `role="status"` and `aria-live="polite"`.
  - Updated `.error-banner` to display sanitized messages and conditionally render the safe `.error-retry-btn`.
- **`platform/desktop-app/src/components/Sidebar.tsx`**:
  - Removed `COMING_SOON_SECTIONS` and disabled navigation buttons loop.
  - Preserved the functional `Settings` button at the bottom of the sidebar.
- **`platform/desktop-app/src/styles/base.css`**:
  - Styled `.chat-panel-header`, `.ai-status-indicator`, `.ai-status-dot`, `.error-banner-actions`, and `.error-retry-btn`.
